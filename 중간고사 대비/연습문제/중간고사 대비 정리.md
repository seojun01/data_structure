## Part 1. 반드시 알아야 할 핵심 내용

### 2주차 — 자료구조와 알고리즘, 시간복잡도
- **자료구조 분류**: 단순(int, float, str) / **선형**(list, linked list, stack, queue, deque — 1:1) / **비선형**(tree, graph, hash table — 1:N, N:N)
- **알고리즘 5조건**: 입력, 출력, 명확성, 유한성, 효과성
- **메모리 영역**: Stack(변수 이름표·참조, 함수 끝나면 정리) / Heap(실제 객체, GC가 정리) / Data / Text
  - 파이썬은 숫자·리스트·객체 모두 Heap에 있고, Stack에는 "어디에 있는지(참조)"만
  - ⚠️ 메모리의 Heap ≠ 자료구조의 Heap(우선순위 큐용 트리)
- **시간복잡도를 "횟수"로 재는 이유**: 하드웨어와 무관하게 공평 비교
- **Big-O**: 상수·낮은 차수 제거, 최고차항만, 최악의 경우 기준
  - 성장 순서: **O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!)**
- **파이썬 연산 비용**

| 연산 | 복잡도 | 이유 |
|---|---|---|
| `list[i]`, `append`, `pop()` | O(1) | 끝에서만 작업 (append는 평균 O(1)) |
| `pop(0)`, `insert(0, x)`, `del list[0]` | **O(n)** | 나머지 원소를 한 칸씩 이동 |
| `x in list` | O(n) | 순차 탐색 |
| `x in set` / `dict[key]` | 평균 O(1) | 해시로 위치 계산 |
| 정렬된 배열 이진 탐색 | O(log n) | 매번 절반으로 |

- 선택 정렬 O(n²) vs 병합 정렬 O(n log n)

### 3주차 — 파이썬·OOP, 연결 리스트
- **OOP 3대 특징**: 캡슐화(`_` protected 관례, `__` private 이름 변형), 상속(IS-A, 부모 → 자식), 다형성(오버라이딩)
- `__init__` 생성자, `self`, `__str__`, `__len__` 매직 메서드
- **배열 vs 연결 리스트**

| | 배열(동적 배열, list) | 연결 리스트 |
|---|---|---|
| 메모리 | 연속 | 흩어짐, 포인터로 연결 |
| 인덱스 접근 | **O(1)** | O(n) |
| 맨 앞 삽입/삭제 | O(n) | **O(1)** |
| 중간 삽입/삭제 | O(n) | 위치를 알면 O(1), 찾기 O(n) |
| 크기 | 동적 배열은 꽉 차면 복사·확장(그 순간만 O(n)) | 가변 |

- **노드 = data + next**, `head`가 첫 노드, 마지막 `next = None`
- **연결 리스트 종류**

| 종류 | 포인터 | 특징 |
|---|---|---|
| 단순(singly) | next | 앞으로만, 삭제 시 직전 노드 필요 |
| 이중(doubly) | prev + next | 양방향, 노드 자신만으로 O(1) 삭제, 메모리 더 씀 |
| 원형(circular) | next | 끝이 head로 연결, 라운드로빈 |
| 이중 원형 | prev + next | 자바 LinkedList, 리눅스 커널 |

- `tail`을 유지하면 맨 뒤 삽입도 O(1)
- 활용: 텍스트 에디터·Undo/Redo(이중), **LRU 캐시(해시맵 + 이중 연결 리스트)**, 라운드로빈(원형)

### 4~5주차 — 스택
- **LIFO**, top 한 곳에서만 입출력, push/pop/peek/isEmpty 모두 O(1)
- 파이썬 list로: `append` = push, `pop()` = pop, `[-1]` = peek / 연결 리스트로: push = insert_front, pop = delete_front (top = head)
- **재귀와 호출 스택**: 호출마다 프레임 push, 종료 시 pop. base case 없으면 **RecursionError**(파이썬 기본 약 1000단계)
- **스택 오버플로**(프레임이 너무 많이 쌓임) vs **버퍼 오버플로**(버퍼를 넘겨 복귀 주소 등 덮어씀 — 보안 공격)
- **괄호 검사**: `(` → push, `)` → 스택 비었으면 False, 아니면 pop. 끝났을 때 스택이 비어야 True
- **중위 → 후위**: 괄호 씌우기 → 연산자를 닫는 괄호 자리로 → 괄호 제거
  - `2 + 3 * 5` → `2 3 5 * +`
- **후위식 계산**: 피연산자 push, 연산자 만나면 2번 pop(먼저 꺼낸 게 **오른쪽** 피연산자) → 계산 → push
- 활용: 브라우저 뒤로가기, Undo, 화면 네비게이션, `git stash`, 팝업 ESC 닫기

### 6~7주차 — 큐, 환형 큐, 덱
- **FIFO**, enqueue는 rear(뒤), dequeue는 front(앞)
- list 큐의 `pop(0)`은 **O(n)** → 해결책이 환형 큐 / `collections.deque`
- **환형 큐 (강의 코드 기준)**: `front` = 맨 앞 원소 칸, `rear` = 다음에 넣을 빈 칸, `count`로 상태 관리
  - enqueue: `arr[rear] = x; rear = (rear + 1) % capacity; count += 1` (count == capacity면 Overflow)
  - dequeue: `x = arr[front]; front = (front + 1) % capacity; count -= 1` (count == 0이면 Underflow)
  - enqueue/dequeue 모두 **O(1)** — 데이터는 움직이지 않고 인덱스만 바뀜
  - `% capacity` 덕분에 끝에 닿으면 0번 칸으로 돌아감 (없으면 IndexError)
  - 가득 참과 비어 있음 모두 **front == rear** → 그래서 `count`가 필요 (다른 방법: 한 칸 비워두고 `(rear+1) % N == front`면 가득 참)

> [!warning] 강의 연습문제의 다른 표기법
> 강의 p.14~15 연습문제는 **front = 첫 원소의 바로 앞 칸, rear = 마지막 원소 칸** 표기를 사용함. 문제에서 어떤 정의를 쓰는지 먼저 확인할 것.

- **Deque**: 양쪽 끝 모두 삽입·삭제 — `append`, `appendleft`, `pop`, `popleft` (모두 O(1))
- **우선순위 큐**: 들어온 순서와 무관하게 우선순위가 높은(숫자가 작은) 것부터. 배열/연결 리스트로 만들면 삽입 또는 삭제 중 하나가 O(n) → **힙(Heap)** 으로 개선 (8주차)
- 큐 활용: 인쇄 대기열, CPU 스케줄링(라운드로빈 → 환형 큐), 패킷 버퍼·키보드 버퍼(링 버퍼), **BFS**, 메시지 큐(Kafka, RabbitMQ)
- **선형 구조의 한계**: 조직도(계층) → 트리, 지하철 노선도(연결 관계) → 그래프

### 8주차(예습) — 이진 트리 기본
- 용어: 루트, 부모, 자식, 리프, 레벨/깊이, 서브트리, 차수
- **순회**: 전위(루트-왼-오), 중위(왼-루트-오), 후위(왼-오-루트), 레벨(BFS, 큐 사용)
- **BST**: 왼쪽 < 부모 < 오른쪽, 중위 순회하면 정렬 순서, 평균 O(log n) / 한쪽으로 치우치면 O(n)
- **힙**: 완전 이진트리 + 부모가 자식보다 작음(최소 힙) → 삽입·삭제 O(log n), 최솟값 확인 O(1)
